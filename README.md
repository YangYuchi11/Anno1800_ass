# 《纪元1800》全自动贸易指挥中心 (Anno 1800 Trade Copilot)

面向《纪元1800》单机玩家的本地 **OCR + RPA** 辅助工具：自动扫描全图岛屿的物资供需、在网页看板上生成贸易航线推荐，并一键在游戏内自动建好航线。

全程离线运行，**不需要 GPU，也不需要联网**（仅首次安装依赖需要网络）。

> 开发状态：核心流程已通过离线冒烟测试（语法检查、依赖安装、中文 OCR 识别、看板 HTTP 接口），尚未在真实游戏内完成端到端验收。

---

## 功能特性

- **F8 · 多页 OCR 扫描**：在 `Ctrl+Q` 生产统计界面，自动归位鼠标、滚回顶部、分页滚动截图，识别岛屿名与每行物资的 `[需求, 供给]`，按物资字典去重合并，计算净盈余（`+`）与净缺口（`-`）。
- **F7 · 全岛链式遍历**：自动点击 `Ctrl+Q` 左侧岛屿列表，逐个岛屿联动执行多页扫描，一键把全图供需导入看板。
- **F9 · 分辨率校准向导**：交互式采样鼠标坐标，实时记录 `Ctrl+R` 航线按钮与 `Ctrl+Q` 截图框，兼容 1080P / 2K / 4K 无边框窗口。
- **F10 · 一键清理货仓**：把当前选中船只的 6 个货仓槽位依次拖到海面并确认销毁，解决贸易航线槽位污染死锁。
- **可视化指挥看板**：`http://127.0.0.1:18000` 内置单页应用，实时轮询本地状态，按供需贪心匹配推荐航线，支持“🚀 一键写入游戏”。
- **纯本地、零云端**：截图、OCR 模型、状态存储、HTTP 服务全部在本机完成。

## 工作原理

```text
游戏画面（Ctrl+Q / Ctrl+R）
   │  mss 区域截图
   ▼
RapidOCR（PP-OCR 检测 + 识别模型，ONNX Runtime 本地推理）
   │  文本行聚类 + 物资字典匹配 + 供需差额计算
   ▼
anno_islands_data.json
   │
   ├── 本地 HTTP :18000 ──► 网页看板（岛屿卡片 / 航线推荐）
   │                              │ 点击“一键写入游戏”
   ▼                              ▼
全局热键 F7 / F8 / F9 / F10    pyautogui RPA 宏 ──► 游戏内自动建航线
```

工具不依赖目标检测模型，而是靠**固定区域截图 + OCR + 坐标校准**定位界面元素，因此实现简单、开销低。

## 安装与启动

### 方式一：一键启动

双击 `start_copilot.bat`。脚本会请求管理员权限、自动安装依赖并启动服务，随后浏览器打开看板。

### 方式二：手动安装

```bat
py -3 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
.venv\Scripts\python anno_copilot.py
```

### 方式三：免环境分发包（换电脑直接用）

用 PyInstaller 打包后的 `AnnoCopilot-win64.zip` 已内置 Python 运行时、OCR 模型和全部依赖，目标电脑**无需安装 Python**：

1. 解压到本地磁盘（路径尽量不含中文和空格）；
2. 双击 `start_as_admin.bat`（弹出 UAC 请求管理员权限）；
3. 浏览器打开 `http://127.0.0.1:18000`，按正常流程使用。

分发包内还附带了 `使用说明.txt`，并可随时用 `AnnoCopilot.exe --selftest` 验证 OCR 引擎是否正常。

> 首次运行可能触发 Windows SmartScreen（程序未签名），选择“更多信息 → 仍要运行”即可。
> 需要 64 位 Windows 10/11；打包机器与目标机器的系统架构需一致（x64）。

如需自行重新打包（需要本机 `.venv` 环境）：

```powershell
powershell -ExecutionPolicy Bypass -File packaging\build_package.ps1
```

脚本会依次执行 PyInstaller、复制启动脚本与说明文档，并在 `dist/AnnoCopilot-win64.zip` 生成分发包。

> 如果系统里的 `python` 指向 Microsoft Store 占位符（运行无输出、退出码 49），请使用 `py -3`，启动脚本已自动处理这一情况。

## 使用流程

1. 将游戏设为**无边框窗口化**并进入存档。
2. 双击 `start_copilot.bat` 启动，浏览器访问 `http://127.0.0.1:18000`。
3. **首次使用按 `F9`**：校准提示会以置顶浮层显示在游戏画面顶部，按提示把鼠标悬停到各界面元素上（无需点击），倒计时结束自动记录并保存配置。
4. 游戏内按 `Ctrl+Q` 打开生产统计：
   - 按 `F8` 扫描当前岛屿；
   - 按 `F7` 自动遍历左侧岛屿列表，批量扫描全图。
5. 在看板中查看供需与推荐航线，点击 **“🚀 一键写入游戏”**，工具会切回游戏自动建航线（执行期间不要移动鼠标）。
6. 紧急中断：把鼠标快速甩到屏幕左上角 `(0, 0)`，触发 pyautogui 的 FAILSAFE。

## 热键一览

| 热键 | 功能 |
| --- | --- |
| `F7` | 批量遍历左侧岛屿并逐个扫描 |
| `F8` | 扫描当前岛屿（多页滚动） |
| `F9` | 启动坐标与截图框校准向导 |
| `F10` | 清空当前选中船只的 6 个货仓槽位 |
| 鼠标甩到左上角 | 紧急中断所有自动操作 |

## 校准与配置

- `anno_coords_config.json`：F9 校准后的本机坐标与截图框，**不会提交到仓库**。
- `anno_islands_data.json`：扫描得到的岛屿供需数据，**不会提交到仓库**。
- 内置默认坐标基于 1920×1080，其他分辨率请务必先执行 F9。

## 常见问题

| 问题 | 处理方式 |
| --- | --- |
| 提示未检测到 `rapidocr_onnxruntime` | 执行 `pip install -r requirements.txt`，或直接使用 `start_copilot.bat` |
| F7–F10 与游戏快捷键冲突 | 修改 `anno_copilot.py` 底部的 `keyboard.add_hotkey` 绑定 |
| 4K 下出现漏行 / 串行 | 调大 `parse_single_page_goods()` 中的行聚类阈值 `22`（像素） |
| 窗口聚焦失败 | 确认游戏窗口标题精确为 `Anno 1800`，或调整 `focus_anno_window()` |
| 写入航线期间看板卡顿 | 内置 `HTTPServer` 是单线程的，宏执行期间轮询会排队，属正常现象 |
| OCR 识别不到物资 | 确认游戏语言为简体中文；物资名需能匹配 `GOODS_CATALOG` |

## 技术栈

- **截图**：`mss`
- **OCR**：`rapidocr_onnxruntime`（PP-OCR 检测 + 识别，ONNX Runtime 本地推理）
- **键鼠自动化**：`pyautogui`、`keyboard`、`pywin32`
- **图像处理**：`Pillow`、`numpy`
- **服务端**：Python 标准库 `http.server` + 内嵌单页 HTML/JS 看板
- **数据**：本地 JSON 文件

## 已知限制

- 依赖游戏内简体中文物资名做匹配，换语言需修改物资字典。
- 坐标校准与本机分辨率、窗口位置绑定，更换显示配置后需重新 F9。
- HTTP 服务为单线程，长宏执行期间看板轮询会短暂阻塞。
- 工具直接模拟输入，不包含存档备份或失败回滚机制。
